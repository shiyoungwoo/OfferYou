# OfferYou UI 重构提示词

这份提示词用于原型网站或高保真设计工具。目标是只改「应用工作台」的 UI，不改简历模板本体。

## 复制使用版

请为 OfferYou 设计一套更像真实产品的「岗位定制工作台」界面。
重点不是继续美化简历模板，而是把上传、校准、改写、确认、预览、导出这条链路做得清晰、稳定、可操作。

### 必须遵守的产品约束

- 不修改 `Professional CN` 和 `ATS Clean` 两套简历模板的视觉结构、颜色、页头样式、正文排版。
- 不新增社区、批量投递、视频面试、照片展示等功能。
- 不把规则兜底伪装成 AI 输出。
- 不展示内部术语，例如 `deterministic`、`fallback stack`、`schema`、`prompt repair`。
- 页面文案要克制、准确、偏工具感，不要宣传腔。

### 这次 UI 的核心目标

1. 让用户一眼看懂当前在处理哪个岗位。
2. 让「匹配度」「岗位能力摘要」「同步预览」放在最显眼的位置。
3. 让简历正文区域成为主舞台，减少右侧杂项信息占用。
4. 让每个模块的「接受 / 编辑 / 拒绝 / AI 微调」操作顺手、清楚、不会混乱。
5. 让确认后的内容立即同步到预览和导出链路，避免前后不一致。

### 页面结构建议

#### 1. 顶部工作台区

- 左侧显示：
  - 当前岗位名称
  - 目标公司
  - 一个简短的岗位定位说明
- 中间显示：
  - 匹配度分数
  - 一句简短解释，例如「主要匹配于 AI 工具、流程设计、跨团队协作」
- 右侧只保留一个主按钮：
  - `同步预览`

#### 2. 个人信息区

- 只展示简历里真实存在的字段。
- 允许补空，但不强制。
- 没有填写的 GitHub、作品集、居住地等字段不要占位显示。
- 如果有英语等级，只放在个人信息区，不要再单独建「补充信息」模块。

#### 3. 简历主内容区

- 按模块分组：
  - 个人优势
  - 工作经历
  - 项目经历
  - 教育背景
- 每个大模块内使用 T 型布局：
  - 左侧：原始内容
  - 右侧：AI 根据 JD 和个人优势后的改写内容
- 右侧顶部只放一句很短的 JD 能力摘要，不要堆说明文。
- 右侧正文下方放操作按钮：
  - `接受`
  - `编辑`
  - `拒绝`
  - `AI 微调`

#### 4. 模块收起规则

- 某个大模块里的所有子项都确认后，自动收起。
- 自动跳到下一个未完成模块。
- 已确认模块再次展开后，仍然可以重新确认并再次收起。
- 收起态要清楚显示完成状态，不要只靠颜色暗示。

### 视觉方向

- 整体偏简洁、专业、稳定。
- 适合互联网和 AI 产品岗位投递。
- 主色使用深蓝，不要亮蓝。
- 卡片、分隔线、留白要统一。
- 减少花哨装饰，避免页面看起来像半成品。
- 文字层级要稳定，标题、模块标题、正文、按钮要有清楚的字号梯度。

### 需要重点修正的体验问题

- 个人优势里的子标题风格必须统一，全部使用同一种加粗深蓝样式。
- 不要把 OCR 断行拆成奇怪的圆点或孤立短词。
- 项目经历和工作经历的换行、缩进、圆点样式要一致。
- 教育背景要保留学校、学历、专业、时间，不要丢本科。
- 预览和导出必须一致。
- 左右两列不要互相抢空间，正文优先。

### 交付标准

- 看起来像可用产品，不像原型草稿。
- 结构清楚，信息密度高，但不拥挤。
- 用户可以在 30 秒内知道下一步该做什么。
- 不改模板本体，只改工作台壳和交互组织。

### 推荐补充文案

- `同步预览`
- `确认无误后导出 PDF`
- `当前为规则兜底`
- `需要补全文本`
- `模块已确认`
- `下一模块`

## 给设计工具的短版提示

设计一个 OfferYou 的岗位定制工作台 UI。保留简历模板冻结不变，只重做应用壳和工作流。顶部展示岗位、公司、匹配度和同步预览按钮；中间是简历主编辑区，按「个人优势 / 工作经历 / 项目经历 / 教育背景」分块，采用左原文右改写的 T 型布局；右侧只保留简短 JD 能力摘要；每个模块下方有接受、编辑、拒绝、AI 微调四个按钮；确认完一组自动收起并跳到下一组；整体使用深蓝、克制、专业的产品风格，避免花哨装饰和半成品感。不要修改简历模板本体。
