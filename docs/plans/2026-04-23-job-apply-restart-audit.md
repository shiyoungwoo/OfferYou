# OfferYou 重启审计与第一轮收口

## 这次重启的判断

当前仓库并不是「没有东西可用」，而是已经有了一条可运行的岗位定制链路，只是在最近一轮 V3 扩张里开始偏离最初的 `job-apply` 原型。

最明显的偏差有三类：

1. **产品重心被稀释**
   - 顶层布局开始突出「Dashboard / Community / Points / 假资料卡」。
   - 这些内容并不属于当前 MVP 的可信主链路，也没有真实数据支撑。
   - 结果是：第一次进入产品时，注意力被带离了最应该打磨的岗位定制流程。

2. **防失真防线被削弱**
   - 预览页曾移除了导出前的显式确认步骤。
   - 这与 `job-apply` 原型强调的「人工确认后再导出最终简历」相冲突。
   - 对 OfferYou 来说，这不是小交互，而是信任边界。

3. **工程状态开始失配**
   - 测试用例与当前实现分叉，出现多处失败。
   - 文件提取链路在 PDF 场景上也出现了不稳定行为。
   - 如果继续在这个状态上叠功能，后面会越来越难判断哪些行为是真的可依赖。

## 重新锚定的原型

这次重启重新把产品锚定回 `job-apply` 主线：

1. 差距分析
2. 建议清单
3. 派生快照
4. 确认导出
5. 投递记录

同时保留「天赋发现」的增强价值，但不让它阻塞第一条岗位定制链路。

## 本轮已经收口的内容

### 1. 重新收口顶层导航
- 去掉把「社区 / 积分 / 假用户资料」当成主界面的设计。
- 改为围绕 `总览 / 岗位定制 / 天赋发现 / 我的资料 / 事实主档` 的结构。
- 在导航中直接写清楚 OfferYou 的三层模型：
  - 事实层
  - 洞察层
  - 表达层

### 2. 岗位定制页重新对齐 `job-apply`
- 页面文案改回以岗位定制为中心。
- 明确展示主链路：
  - 输入 JD 与简历
  - 生成差距分析与建议清单
  - 生成岗位快照并导出
- 输入表单统一改为中文，并补回「绝对防失真」提示。

### 3. 导出链路重新补上确认边界
- 恢复导出前的显式确认复选框。
- 导出成功后直接给出「查看这次简历记录」入口。
- 这一步是产品信任边界的一部分，不再省略。

### 4. 修复当前最直接的工程脱轨
- 修复 PDF 文本提取链路中 `pdf-parse` 的导入问题。
- 区分 `full_text` 与 `partial_text`，避免把原始回退提取误判为完整提取。
- 同步修复与更新一批测试用例，使其重新反映当前真实行为。

## 仍然保留但暂不主推的内容

以下内容目前仍可作为后续方向存在，但不再作为主界面的核心入口：

- `community`
- `prep`
- 广义职业陪伴仪表盘

这些方向只有在岗位定制主链路稳定之后，才值得继续产品化。

## 下一轮建议

### 产品层
- 把分析页中的「建议采纳 -> 新事实待确认 -> 快照生成」串得更显式。
- 在预览页补一个「本次快照引用了哪些事实」的小面板。

### 工程层
- 增加一条真正的端到端用例：创建 draft -> 采纳建议 -> 生成 snapshot -> 导出 PDF。
- 把 `dashboard`、`community`、`prep` 的信息结构统一归入「规划中」，避免再次抢主链路注意力。

### 数据层
- 继续坚持 `Master` 不被岗位表达污染。
- 将来如果引入更多 AI 生成步骤，也必须保持：
  - 事实写入需要确认
  - 洞察与表达分层
  - 导出前人工确认
