# OfferYou AI 与代码职责边界 v3.3

## 1. 核心结论

OfferYou 不是「规则工作流外面套一层 AI」，而是「Agent 内核 + Web 交互界面」。

代码负责确定性工作：保存、路由、状态、文件解析、格式转换、导出、校验、权限和可追溯。

AI 负责非确定性判断：理解、比较、取舍、归因、改写、策略、校验和面试准备。

天赋挖掘不是可选增强。完成天赋挖掘后，OfferYou 才进入最大能力模式。天赋画像提供「用户模型」，JD 提供「机会模型」，简历事实提供「证据模型」。Agent 的核心任务是在三者之间找到最适合用户的职业表达。

## 2. 三种运行模式

| 模式 | 触发条件 | 能做什么 | 不能声称什么 |
|---|---|---|---|
| 基础编辑模式 | 模型不可用，或用户只想手动编辑 | 结构化简历字段、手动编辑、模板预览、PDF 导出 | 不能声称 AI 定制、AI 优化、AI 判断适配度 |
| 岗位定制模式 | 模型可用，有简历和 JD，但未完成天赋挖掘 | JD 理解、简历结构校准、岗位定制改写、事实校验、快照和面试准备 | 不能声称已最大化发挥个人潜力 |
| 天赋驱动 Agent 模式 | 模型可用，有简历、JD 和 TalentProfile | 基于用户底层优势、可迁移能力和 JD 的深度定制简历与面试准备 | 不能用规则兜底冒充深度判断 |

## 3. 节点职责总表

| 节点 | 主责 | 是否必须 AI | 代码职责 | AI 职责 | 失败处理 |
|---|---|---:|---|---|---|
| 文件接收 | 代码 | 否 | 上传、类型校验、存储、哈希、文件大小限制 | 无 | 拒绝无效文件，提示原因 |
| PDF / DOCX / TXT 解析 | 工具 + 代码 | 否 | 调用 OpenDataLab PDF、DOCX parser、OCR 工具，输出原始文本和布局线索 | 仅在需要视觉校准时介入 | 解析失败进入人工粘贴文本 |
| 视觉布局校准 | AI | 是，若原始解析低置信 | 生成图片、页面、文本候选供模型读取 | 识别版面、栏目、表格、模块边界、OCR 异常 | 模型不可用时标记「需人工确认」，不自动下游改写 |
| 简历结构校准 | AI 主责，代码守边界 | 是 | 保存 `CalibratedResumeProfile`、字段 schema、置信度、人工确认状态 | 判断个人信息、个人优势、工作经历、项目经历、教育背景、补充信息归属 | 低置信项必须人工确认 |
| 天赋挖掘 | AI | 是 | 记录对话、保存 TalentProfile、版本化洞察 | 通过深度问题提炼优势、能量来源、可迁移能力、风险盲区、表达策略 | 未完成时进入岗位定制模式，不进入最大能力模式 |
| JD 理解 | AI | 是 | 保存 JD 原文、截图、来源、结构化结果 | 提取公司、岗位、硬要求、核心能力、加分项、避免项、关键词 | 模型不可用时停止 AI 定制，只允许人工编辑 |
| 匹配度与差距分析 | AI 主责，代码辅助 | 是 | 计算文本重合、展示分数、保存差距项 | 判断真实匹配、可迁移能力、强弱相关、风险与机会 | 规则分数只能标记为「粗略参考」 |
| 改写策略 | AI 主责，代码约束 | 是 | 控制输出格式、模块顺序、字数上限、事实边界 | 决定重点强化、弱相关压缩、个人优势如何对齐 JD | 模型不可用时不得生成「AI 优化改写」 |
| 改写建议 | AI | 是 | 按建议状态保存、绑定 candidateId、展示 T 型结构 | 生成可直接进入简历的 `afterText`、`jdAbility`、`reason`、`factAnchors` | 失败则提示模型问题，允许用户手动编辑 |
| 事实校验 | AI + 代码 | 是 | 检查公司、时间、学历、数字、重复、模块归属、文本相似度 | 判断是否过度包装、是否违背原事实、是否偏离 JD | `fail` 不允许普通接受，只能编辑或重新 AI 微调 |
| 人工确认 | 代码 | 否 | 接受、拒绝、编辑、微调状态机；模块自动收起 | 微调动作才调用 AI | 并发冲突时提示刷新或重试 |
| FinalResumeDraft 合成 | 代码 | 否 | 只读取已确认内容，合成唯一草稿 | 无 | 缺少关键字段时提示人工补充 |
| 预览与 PDF 导出 | 代码 | 否 | 使用冻结模板渲染，确保预览和导出一致 | 无 | 导出失败提示重试，不改模板视觉 |
| 面试准备 | AI | 是 | 从 FinalResumeDraft 和 JDInsight 取数，保存结果 | 生成自我介绍、问题、追问、风险回答、反问问题 | 模型不可用时不生成伪面试准备 |
| 投递记录 | 代码 | 否 | 保存公司、岗位、版本、PDF、面试准备、时间 | 可总结复盘，但不是必需 | 写入失败提示用户 |

## 4. 必须 AI 的节点

以下节点不能用确定性规则替代，也不能用规则兜底冒充 AI：

- 天赋挖掘与 TalentProfile 生成。
- JD 理解。
- 简历结构校准中的模块归属判断。
- 视觉布局校准。
- 匹配度与差距分析中的能力判断。
- 改写策略。
- 简历改写。
- 事实可信度的语义判断。
- 面试准备。
- 职业方向建议。

这些节点一旦模型不可用，页面只能进入「人工编辑 / 人工确认 / 规则参考」状态，不能继续生成看似完整的 AI 结果。

## 5. 应该代码完成的节点

以下节点不应交给模型主导：

- 文件上传、MIME / 扩展名校验、大小限制。
- 文件存储、哈希、版本管理。
- OpenDataLab PDF、DOCX、TXT 等工具调用。
- 数据库读写、JSON 安全解析、事务和并发保护。
- JobApplyRun 状态机。
- 建议接受、拒绝、编辑、微调的状态切换。
- FinalResumeDraft 合成。
- 模板渲染、分页、PDF 导出。
- 空字段隐藏。
- 预览与导出一致性检查。
- API Key 安全、日志脱敏。
- 测试、质量报告和 Git 同步。

这些节点必须稳定、可测试、可回归。模型不应参与确定性状态修改。

## 6. 混合节点的边界

### 6.1 PDF 解析

工具先做文本和布局提取。若文本清晰、模块边界稳定，代码可以进入候选结构；若出现乱码、错栏、页眉页脚混入正文、项目归属不明，必须交给 AI 校准。

### 6.2 简历结构校准

代码只提供候选切块和 schema。最终模块归属由 AI 判断。低置信项进入人工确认，不能直接下游生成建议。

### 6.3 匹配度

代码可以计算关键词覆盖率和基础分。最终匹配度必须由 AI 基于 JD、简历事实和 TalentProfile 综合判断。页面应区分「规则参考分」和「AI 判断分」。

### 6.4 Verifier

代码负责硬规则：公司名、时间、学历、数字、重复、空字段、模板长度。AI 负责语义规则：是否夸大、是否偏离事实、是否对 JD 有真实帮助。

## 7. 天赋挖掘在 Agent 架构中的位置

天赋挖掘不是「首页营销功能」，而是 OfferYou 的 User Model Builder。

`TalentProfile` 至少包括：

- 核心优势。
- 能量来源。
- 高质量输出场景。
- 可迁移能力。
- 反复被别人认可的能力。
- 容易被误解或低估的能力。
- 与目标岗位相关的表达策略。
- 不适合过度包装的边界。

岗位定制时，Agent 必须读取：

- `CalibratedResumeProfile`：事实证据。
- `JDInsight`：岗位机会。
- `TalentProfile`：用户潜力与表达方向。

只有三者同时存在时，OfferYou 才能输出「更适合用户、最大化发挥用户潜力」的简历。

## 8. 对后续 Agent 的硬约束

- 不允许把规则生成内容命名为「AI 优化改写」。
- 不允许把 `deterministic_fallback` 作为正式投递结果。
- 不允许把 JD 文本当作候选人事实依据。
- 不允许让未确认的 OCR / 解析文本直接进入 PDF。
- 不允许接受建议后绕过 FinalResumeDraft。
- 不允许为了排版稳定而牺牲事实完整。
- 不允许为了页面好看而改变已冻结模板。
- 不允许遗忘天赋挖掘在 OfferYou 中的核心地位。

## 9. 与 `job-apply` Skill 的关系

`job-apply` Skill 的优势不是页面，而是模型在完整上下文中的判断能力。OfferYou 要产品化的是这种能力：

- Skill 的差距分析，对应 OfferYou 的 JDInsight + TalentProfile + GapAnalysis。
- Skill 的建议清单，对应 OfferYou 的 RewriteSuggestion。
- Skill 的人工确认，对应 OfferYou 的 T 型确认区。
- Skill 的稳定 PDF，对应 OfferYou 的 FinalResumeDraft + 冻结模板。
- Skill 的面试准备，对应 OfferYou 的 InterviewPrep Agent。

因此，OfferYou 的 Web 价值不是替代 Agent，而是让 Agent 工作流可确认、可编辑、可追溯、可复用。
